# CU-07 · Registrar el seguimiento diario

| Campo | Contenido |
|---|---|
| **Actor principal** | Paciente |
| **Objetivo** | Registrar los datos del día para que su progreso y su siguiente plan alimenticio se calculen con información real. |
| **Precondición** | El paciente tiene la sesión iniciada y su estatura registrada. |
| **Escenario principal** | 1. El paciente elige "Registrar ahora" en el panel principal.<br>2. El sistema muestra el registro del día con dos secciones: "De tus dispositivos", con los datos que ya llegaron y el dispositivo de origen, y "Por registrar", con los datos que faltan.<br>3. El paciente revisa los datos que llegaron de sus dispositivos.<br>4. El paciente captura los datos que faltan, como el agua y los alimentos del desayuno, la comida y la cena.<br>5. El sistema verifica que cada valor esté dentro del rango permitido.<br>6. El paciente elige "Guardar registro".<br>7. El sistema guarda el registro del día y actualiza sus indicadores.<br>8. El sistema muestra "Tu día quedó registrado" con el estado "Completo", el peso y el IMC del día.<br>9. El paciente elige "Ir al inicio" y el sistema muestra el panel principal. |
| **Flujos alternos** | **1a. Hay días anteriores sin registro (RF-009, RF-032):**<br>1a1. El panel principal muestra "Tienes N días sin registro" y aclara que puede registrar hoy sin completarlos.<br>1a2. Si el paciente elige "Registrar ahora", esos días quedan como "Sin registro" y el caso continúa en el paso 2.<br>1a3. Si el paciente elige "Registrar un día anterior", el sistema muestra los días sin registro de los últimos 30 días; el paciente elige uno y el caso continúa en el paso 2 con la fecha de ese día.<br><br>**2a. Un dispositivo no envió algún dato (RF-008):**<br>2a1. El sistema marca el dato como "Sin dato" del dispositivo que corresponde, por ejemplo "Sin dato de la báscula", y lo pasa a "Por registrar".<br>2a2. El caso continúa en el paso 3 y el paciente captura ese dato en el paso 4.<br><br>**2b. El paciente no tiene dispositivos vinculados (RF-008):**<br>2b1. El sistema muestra todos los datos en "Por registrar".<br>2b2. El caso continúa en el paso 4.<br><br>**3a. Un dato del dispositivo es incorrecto (RF-010):**<br>3a1. El paciente elige "Corregir un dato" y corrige el valor como se describe en CU-08.<br>3a2. El sistema reemplaza el dato y regresa al registro del día.<br>3a3. El caso regresa al paso 3.<br><br>**5a. Un valor está fuera de rango (RNF-CON-002):**<br>5a1. El sistema no acepta el valor, señala el campo, muestra el rango permitido y, si el valor dividido entre 10 queda dentro del rango, lo sugiere; por ejemplo, para 724 kg muestra "Debe estar entre 20 y 300 kg. ¿Quisiste escribir 72.4?".<br>5a2. El paciente corrige el valor.<br>5a3. El caso regresa al paso 5.<br><br>**6a. El paciente no captura todos los datos (RF-031):**<br>6a1. El paciente elige "Guardar lo que llevo".<br>6a2. El sistema guarda los datos capturados, marca los demás como "Sin registro" y muestra el día como "Incompleto" (RNF-CON-001).<br>6a3. Si el paciente elige "Completar ahora", el caso regresa al paso 4 con los datos ya guardados.<br>6a4. Si el paciente elige "Ir al inicio", el caso continúa en el paso 9 y el día queda "Incompleto" hasta que lo complete. |
| **Postcondición** | El registro del día queda guardado como "Completo" o "Incompleto". Los datos que no se capturaron quedan como "Sin registro" y no se reemplazan por valores estimados. |
| **Requisitos que realiza** | RF-007, RF-008, RF-009, RF-010, RF-012, RF-031, RF-032, RNF-USA-001, RNF-CON-001, RNF-CON-002 |
| **Relaciones** | Es extendido por CU-08 Corregir un registro en el punto de extensión "dato incorrecto" (flujo 3a). |
| **Pantallas del prototipo** | P02 Panel principal, P02-E1 Panel con días sin registro, P03 Registro del día, P03-E1 Dato sin llegar del dispositivo, P03-E2 Valor fuera de rango, P03-A Corregir un dato, P04 Día registrado, P04-E1 Día guardado incompleto |
