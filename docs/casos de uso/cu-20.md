# CU-20 · Desactivar una cuenta

| Campo | Contenido |
|---|---|
| **Actor principal** | Administrador |
| **Objetivo** | Impedir que un usuario siga entrando al sistema sin borrar su información. |
| **Precondición** | El administrador tiene la sesión iniciada. |
| **Escenario principal** | 1. El administrador abre la sección "Usuarios".<br>2. El administrador busca al usuario por nombre o correo.<br>3. El sistema muestra los usuarios que coinciden, con su rol y su estado.<br>4. El administrador elige al usuario y selecciona "Desactivar".<br>5. El sistema pide confirmar.<br>6. El administrador confirma.<br>7. El sistema desactiva la cuenta y conserva su información.<br>8. El sistema muestra la cuenta con el estado "Desactivada" e indica que su información se conserva.<br>9. El administrador elige "Listo". |
| **Flujos alternos** | **3a. Ningún usuario coincide con la búsqueda (RF-029):**<br>3a1. El sistema indica que no encontró usuarios.<br>3a2. El administrador corrige la búsqueda.<br>3a3. El caso regresa al paso 2.<br><br>**4a. La cuenta elegida ya está desactivada (RF-029):**<br>4a1. El sistema no muestra la opción "Desactivar".<br>4a2. El caso regresa al paso 3 para que el administrador elija otro usuario.<br><br>**6a. El administrador cancela (RF-029):**<br>6a1. La cuenta sigue activa.<br>6a2. El caso regresa al paso 3.<br><br>**7a. La cuenta es de un nutriólogo (RF-029):**<br>7a1. Además de desactivar la cuenta, el sistema deja de mostrar sus horarios a los pacientes.<br>7a2. El sistema marca sus citas pendientes o confirmadas como "Cancelada" para los pacientes.<br>7a3. El caso continúa en el paso 8. |
| **Postcondición** | El usuario ya no puede iniciar sesión y su información se conserva. |
| **Requisitos que realiza** | RF-029, RNF-SEG-003 |
| **Pantallas del prototipo** | P15 Usuarios, P15-C Cuenta desactivada |
